# 蓝海方法论：从「躲开红海」到「创造一个维度」

本文件补上工具的结构性盲区。

`red_ocean_scanner` 的三个模式（scan / ladder / geo）都只能在**已有市场**里
找空位——换个词、换个地区、换个更窄的人群。但真正持久的蓝海往往不是"找到"的，
是**创造**出来的：重构价值曲线，让竞争变得无关。

工具测不出来这一层，因为它测的是别人的供给。这一层要靠人来想。本文件提供
可操作的思考框架。**当 scan 给出绿灯但你担心「别人一周就能抄」时，读这一节。**

---

## 一、先补上一个工具测不到的东西：护城河

工具只回答「有没有人在做」。它不回答**「你做出来之后守不守得住」**。
这两件事完全不同，而且第二个更决定长期收益。

### Power = Benefit + Barrier

Hamilton Helmer 在《7 Powers》里的核心公式：一个优势要成为持久的 Power，
必须同时具备两半——

- **Benefit（好处）**：更好的成本、更高的定价、更好的质量
- **Barrier（壁垒）**：竞争对手无法在不伤害自己现有生意的前提下复制它

**只有 Benefit 没有 Barrier，优势会被竞争抹平。** 大多数看起来赚钱的生意
其实一个 Power 都没有——它们的利润只是暂时的。

**自查方法**：说出你的优势后，追问一句「如果这周有 10 个人抄我，我靠什么
还活着？」答不出来就是只有 Benefit。

### 七种 Power，以及单人开发者实际能拿到哪些

这是把 Helmer 的分类落到「一个人、无资本、无团队」的约束下：

| Power | 壁垒机制 | 单人可得性 | 怎么拿到 |
|---|---|---|---|
| **Counter-positioning** 反定位 | 在位者不能跟进，因为会伤害自己现有生意 | ⭐⭐⭐ **最可得** | 用他们不敢用的商业模式打（免费+增值、本地处理不联网、按次收费） |
| **Switching costs** 转换成本 | 用户迁移要付出累积投入 | ⭐⭐⭐ **最可得** | 让产品承载用户数据/配置/历史，越用越难走 |
| **Cornered resource** 独占资源 | 稀缺或独家资产 | ⭐⭐ | 独家数据、独家合作、行业内部知识、特定执照 |
| **Branding** 品牌 | 多年一致体验建立的信任 | ⭐ **慢** | 长期垂直深耕，把内容资产做成信任 |
| **Process power** 流程能力 | 不透明、路径依赖的复杂流程 | ⭐⭐ | 极难复制的运营细节（常需团队） |
| **Scale economies** 规模经济 | 单位成本随规模下降 | ✗ 基本不可得 | 需要资本 |
| **Network economies** 网络效应 | 用户越多价值越高 | ✗ 基本不可得 | 需要双边冷启动资源 |

**给单人开发者的结论**：优先找**反定位**和**转换成本**。这两种不需要资本、
不需要团队、不需要时间积累，而且恰好是个人相对大厂的优势区——
大厂不敢做的定价模式、不敢碰的窄场景、不屑于做的脏活，都是反定位的来源。

### Power 的时间窗

Helmer 的「Power Progression」指出不同 Power 在生意不同阶段才可得：

```
起源期 → 反定位（唯一从一开始就可得）
起飞期 → 规模经济、转换成本、网络效应
稳定期 → 品牌、流程能力
```

**起源期就该想清楚定位，而不是等有了产品再补战略。** 这是反直觉的：
大多数人把战略当成「有 PMF 之后的事」，但反定位的窗口恰恰在最早。

### 把护城河接进工作流

```
scan 给出绿灯（供给薄 + 需求有）
        ↓
问：我的 Barrier 是什么？（上表七选一）
        ↓
答不出 → 绿灯降级为「短期机会」：能赚钱但守不住，适合当现金流，别当事业
答得出 → 才是真正的蓝海候选
```

工具在绿灯时会附上这个追问，但**判断必须你自己做**——它取决于你的
具体资源，不是市场数据能回答的。

## 二、ERRC 网格：不是找空位，是重构价值曲线

前面的 ladder 模式只在**一个方向**上收窄（更窄的人群/场景）。
ERRC 是四个方向同时动，用来把红海的价值曲线重新画一遍。

对**你所在品类**，逐条回答四个问题：

| 动作 | 问题 | 作用 |
|---|---|---|
| **Eliminate** 消除 | 行业习以为常、但客户其实不在乎的因素是什么？ | 降成本 |
| **Reduce** 减少 | 哪些因素被过度供给、可以砍到远低于行业标准？ | 降成本 |
| **Raise** 提升 | 哪些因素该拉到远高于行业标准？ | 提价值 |
| **Create** 创造 | 行业从未提供过的因素是什么？ | 开新需求 |

关键：**Eliminate 和 Reduce 降低成本，Raise 和 Create 提升价值。**
四个一起做，才能同时做到差异化和低成本——这是蓝海的定义，
也是为什么它绕开了「要么便宜要么好」的取舍。

### 套到软件品类上的例子

以「发票/记账工具」为例（红海品类），四个动作可以这样展开：

- **Eliminate**：账号注册、云端上传、模板选择器（用户其实不在乎）
- **Reduce**：支持的发票格式数量（从 50 种砍到 3 种主流）
- **Raise**：批量处理量、识别准确率、离线可用性
- **Create**：数据不出本机（合规部门敢批）、按次付费不订阅、
  和现有 ERP 的零配置对接

注意 **Create 那一栏才是蓝海**。「数据不出本机」让竞品很难跟——
跟进意味着放弃云端订阅收入（反定位），这正是 Barrier。

### 三条检验标准

做完 ERRC 后，用蓝海战略的三条测试自查：

1. **重点突出（Focus）**——价值曲线有没有明确的取舍，还是什么都想要？
2. **另辟蹊径（Divergence）**——曲线形状是否明显偏离行业？
   和竞品形状一样就是没做出蓝海。
3. **令人信服的口号（Compelling tagline）**——能不能一句话说清
   「我和他们有什么不同」？说不清就是没想清。

## 三、六路径：系统性越过行业边界找需求

ERRC 是「怎么重构」，六路径是「往哪看」。当你觉得候选池枯竭时，
按这六条路径逐条问，比继续换关键词有效得多。

| 路径 | 问什么 | 落到具体动作 |
|---|---|---|
| **1. 替代行业** | 客户**不买你的品类**时，用什么替代？ | 列出所有替代方案（含 Excel、微信群、纸质），问他们为什么选那个 |
| **2. 战略集团** | 行业里不同定位的玩家之间，为什么没人做中间地带？ | 找「高端太贵、低端太难用」之间的空档 |
| **3. 买方群体** | 你一直盯着买单的人，但**使用者/影响者**的需求被忽略了吗？ | 谁在用但不管采购？谁的意见决定采购？ |
| **4. 互补品** | 你的产品前后，客户还要忍受什么？ | 把上下游最烦的一步吞进自己产品 |
| **5. 功能与情感** | 行业是靠功能还是靠情感竞争？反过来会怎样？ | 功能型行业加情感（社区/身份），情感型加功能（工具化） |
| **6. 时间** | 如果趋势按现在的方向走 10 年，需求会变成什么？ | 提前为必然发生的变化做准备 |

**路径 3 和 4 对单人开发者最实用**：买方群体错位和互补品整合，
都不需要资本，只需要注意到别人没注意的使用者。

## 四、Jobs to be Done：把「产品」换成「任务」

一个防止想偏的提问方式：**客户不是买产品，是雇一个东西来完成某件事。**

不要问「谁会用发票工具」，要问「什么情况下一个人必须处理发票，
而他手上现有的东西都办不好？」——后者会带出场景、频率、替代方案和
容忍度，这些才是判断依据。

**JTBD 的边界**：它在深度 B2B 场景最弱（采购决策涉及多人、
政治和合规，不是单个人的「任务」）。B2B 方向请用 ERRC + 买方群体分析代替。

## 五、这一层为什么工具替代不了

必须说清楚，避免误以为 scan 绿灯就等于蓝海：

- **工具测的是「已被表达的需求」**（搜索词、仓库、上架产品）。
  蓝海常常来自**尚未被表达的需求**，它在数据里不存在。
- **工具测不出 Barrier**。供给薄可能因为没人做，也可能因为**做过的人
  都守不住**。后者在数据上看起来和你想要的一模一样。
- **工具测不出组织能力**。反定位要求你能不能交付那个「他们不敢做的模式」，
  这是关于你的事实，不是关于市场的事实。

**所以正确用法是**：工具负责**排除**（这是它擅长的、可验证的），
框架负责**创造**（这是它替代不了的）。不要指望前者给你灵感。
