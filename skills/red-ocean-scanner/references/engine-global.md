# 全球市场引擎（global）细节

这份是从 SKILL.md 拆出来的引擎专属知识。**只在做全球/英文市场分析时读。**
用法入口见 SKILL.md 的「选择市场引擎」。

## 七-G、全球引擎怎么工作

```bash
python3 scan.py --engine global "keyword"
```

**供给（计入评分）**
- GitHub 仓库数：<300 极低 / <1500 低 / <5000 中 / <20000 密集 / ≥20000 红海
- 头部仓库 star：≥2000★ = 已有成熟开源替代品（否决项）；<50★ 且仓库少
  = 没有赢家，缺口典型形态

**参考（不计分）**
- GitHub issues 数量与未关闭数——混合 bug 与功能请求，需人工读

### 需求维度取数要看的两个数字

需求 = Google + Bing + DDG 三源自动补全的合并结果，输出里的
`google:N bing:M ddg:K` 是**各源实际贡献条数**，先看它再看结论：

- **某一源为 0，先怀疑取数失败，不要读成「那个源没建议」。** 实测过一次
  `google:5 bing:0 ddg:0`：Bing 请求成功返回 12 条，全被通用词过滤器误杀
  （见 `references/data-sources.md` ②-b）。需求强度因此被系统性低估。
- **网络受限时 Google 补全会拿不到**（本机实测 TLS 握手间歇超时，DNS 解析到
  被污染 IP）。此时只剩 Bing 一源——结论仍可用，但要意识到"三源交叉验证"
  实际退化成了单源。
- 查询本身会被三源回显在第一位，它**不计入**「商业意图 N 条」。

## 八-G、全球引擎的校准锚点

只列最常用的几个方向，用于快速校验你的直觉是否跑偏：

| 方向 | 矩阵裁决 | 卡在哪 |
|---|---|---|

本文件不重复维护，避免两处不一致。

## 九-G、全球引擎的付费验证（人工，必做）

GitHub 供给稀薄**只证明没人做，不证明有人买**。全球市场的验证路径：

```
1. 找该行业的垂直社区（不是 Reddit 主版，是行业论坛/Facebook 群/LinkedIn 群）
2. 读真实抱怨，找"现在怎么解决"的描述
3. 看有没有人在卖同类方案：Google "<关键词> software pricing"
   （注意：本 skill 无法自动搜 Google，必须人工）
4. 挂落地页收邮箱，看转化
```

**关键区别**：中文市场看闲鱼成交（能看到真实成交记录），
全球市场看定价页和评测站——两者的"事实"来源不同。
