# 避红海扫描 · Red Ocean Scanner

## 一句话原则

**存量少不等于机会，存量少可能只是没人关心。** 判断必须同时看需求和供给，
而且**需求侧的"愿不愿意掏钱"比供给侧的"有没有人做"更重要**。

这个 skill 的存在就是为了防止一个具体错误：**只看供给就下结论。**
下面所有规则都是从真实反例里总结的，不是理论。

## 一、选择市场引擎

两个市场的**可靠信号完全不同**，所以是两个独立引擎，不是一个参数开关。
强行合并会得到一个两个市场都不准的工具。

```bash
cd <skill目录>

python3 scan.py --engine global "veterinary clinic software"   # 全球/英文
python3 scan.py --engine cn     "代账公司对账单"                  # 中文
python3 scan.py --engine both   "invoice excel"                 # 同词双市场对比
python3 scan.py --list-engines
```

| 引擎 | 市场 | 可靠信号 | 产出 |
|---|---|---|---|
| `global` | 全球/英文 | GitHub 仓库密度 + star 分布 | 开发者生态视角 |
| `cn` | 中文 | 微信内容存量 + 360 相关搜索 | 搜索意图视角 |

也可以直接调用底层脚本（`global_scan.py` / `red_ocean_scan.py`）。
统一入口会自动注入正确的词间冷却，**推荐始终用 `scan.py`**。

纯 Python 3.8+ 标准库，**无需 pip install，不需要 API key**。

# 第一部分：通用判读

## 二、怎么读裁决

| 裁决 | 分 | 含义 | 动作 |
|---|---|---|---|
| 🟢 绿 | 8–10 | 值得投入一周验证 | 去做付费验证，别急着写代码 |
| 🟡 黄 | 5–7 | 有硬伤 | 换更窄的关键词重扫，或只当引流工具 |
| 🔴 红 | 0–4 | 别做 | 放弃，**不要靠加功能挽救** |
| 🟡 黄(不完整) | — | 数据没取到 | 稍后重跑，**不要在这个结论上做决定** |

**「否决项」比分数重要。** 出现任何一条否决项，无论分数多高都要停下来。
否决项是「这个方向从结构上就不成立」，不是「需要努力克服」。

**分数只反映供给健康度，不反映需求大小。** 需求必须人工验证（见第八节）。

## 三、信号可靠性分级（本 skill 最重要的方法论）

实测得出的分级。**只有可靠信号计入评分**，噪声信号一律降级为参考。

### 可靠 — 计入评分

| 信号 | 引擎 | 实测区分度 |
|---|---|---|
| GitHub 仓库数 | global | **4000 倍量级**：todo app 90,582 vs 兽医排班 117 |
| 头部仓库 star 分布 | global | 14,139★（habit tracker，红海）vs 2★（殡葬管理，缺口） |
| 微信内容存量 | cn | 8580（摸鱼，红海）vs 511（代账对账单，缺口） |
| 标题信号（付费工具/自己做） | cn | 能区分"有人靠它赚钱"与"壁垒已归零" |
| 360 相关搜索词 | cn | 真实搜索行为，高购买意图词可数 |

### 噪声 — 仅作参考，不计分

| 信号 | 为什么不可靠 |
|---|---|
| **StackOverflow 搜索** | 模糊匹配，噪声极大。实测 `invoice excel` 匹配到 Automapper 问题；`funeral home management` 匹配到 UIPickerView 问题。**已停用** |
| **npm / PyPI 搜索** | 同样是模糊匹配。`sports team scheduling` 返回 52,825 个包，无意义 |
| GitHub issues | 混合 bug 报告与功能请求，需人工读标题判断 |

### 设计原则：宁可漏判，不可误判

**一个会给出错误绿灯的工具，比没有工具更糟。** 所以本 skill 只把可验证的
信号计入评分，宁可少给绿灯，也不把噪声当证据。

## 四、不可访问的数据源（实测，别浪费时间重试）

| 源 | 状态 |
|---|---|
| Google / Google Trends / Google autocomplete | ❌ 网络不可达 |
| Reddit / DuckDuckGo / Wikipedia / YouTube | ❌ 网络不可达 |
| Product Hunt / G2 / Capterra / AlternativeTo | ❌ Cloudflare 拦截 |
| Bing（中英文） / 百度 / 头条 / 神马 | ❌ 固定套话或 JS 空壳 |
| 知乎 / B站 / 小红书 / 抖音 / 闲鱼 | ❌ 403 / 412 / 登录墙 |
| Chrome Web Store | ❌ 网络不可达 |

**这导致一个明确的局限：本 skill 看不到消费级市场。**
两个引擎都是**开发者/搜索生态视角**，对纯消费类产品判断力弱。
这是 limitation，不是可以绕过的实现细节——**遇到消费级方向要主动说明这一点。**

## 五、盲点扫描（每次分析都要过一遍）

这些不出现在任何平台清单里，但决定同样的努力能换多少钱：

1. **「有人做但做得烂」永远比「没人做」值钱。** 没人做常常是因为不赚钱。
2. **钱在重复收费里。** 订阅 > 买断 > 广告分成。内容平台分成是最差的一档。
3. **买家要选「正在赚钱的人」**（卖家、代账公司、诊所、从业者），不是
   「想赚钱的人」（同行、小白）。前者算得清 ROI，后者是焦虑税且窗口在关。
4. **分发先于产品。** 先答"用户怎么找到我"，再做产品。
5. **不用登录/版号/备案的形态优先**，把合规成本压到零。
6. **AI 含量越高的环节越不值钱。** 内容生产已被 AI 打平；判断、信任、合规
   这些 AI 做不了的环节在升值。
7. **开源会压制付费意愿。** 如果头部是成熟开源项目，买家是开发者时基本收不到钱；
   但换成企业买家可能仍然成立。这条在全球市场尤其重要。

## 六、标准工作流

1. 判断市场：目标用户在中文区还是英文区？选对应引擎
2. 列 6–10 个候选关键词（从自己的抱怨、身边人的抱怨里找）
3. 跑扫描，拿到红黄绿排名
4. **只对绿灯项**做付费验证（见第八节）
5. 按盲点清单复核
6. 只留一个，花一周做落地页，**不写产品代码**
7. 判断标准：有没有陌生人在 6–8 周内主动掏钱

# 第二部分：全球市场引擎（global）

## 七-G、全球引擎怎么工作

```bash
python3 scan.py --engine global "keyword"
```

**供给（计入评分）**
- GitHub 仓库数：<300 极低 / <1500 低 / <5000 中 / <20000 密集 / ≥20000 红海
- 头部仓库 star：≥2000★ = 已有成熟开源替代品（否决项）；<50★ 且仓库少
  = 没有赢家，缺口典型形态

**参考（不计分）**
- GitHub issues 数量与未关闭数——混合 bug 与功能请求，需人工读

## 八-G、全球引擎的校准锚点

实测值，可直接对照：

| 方向 | 仓库数 | 头部★ | 分 | 裁决 |
|---|---|---|---|---|
| funeral home management | 23 | 2 | 9 | 🟢 |
| veterinary clinic scheduling | 117 | 13 | 9 | 🟢 |
| invoice excel | 2,262 | 411 | 5 | 🟡 |
| habit tracker | 60,479 | 14,139 | 2 | 🔴 |
| todo list app | 90,582 | 2,121 | 2 | 🔴 |

**为什么 `invoice excel` 只有 5 分**：2,262 个仓库不算少，且有 411★ 玩家。
它是"能做但要明确差异化"，不是"蓝海"。

## 九-G、全球引擎的付费验证（人工，必做）

GitHub 供给稀薄**只证明没人做，不证明有人买**。全球市场的验证路径：

```
1. 找该行业的垂直社区（不是 Reddit 主版，是行业论坛/Facebook 群/LinkedIn 群）
2. 读真实抱怨，找"现在怎么解决"的描述
3. 看有没有人在卖同类方案：Google "<关键词> software pricing"
   （注意：本 skill 无法自动搜 Google，必须人工）
4. 挂落地页收邮箱，看转化
```

**关键区别**：中文市场看闲鱼成交（能看到真实成交记录），
全球市场看定价页和评测站——两者的"事实"来源不同。

# 第三部分：中文市场引擎（cn）

## 七-C、中文引擎怎么工作

```bash
python3 scan.py --engine cn "关键词"
```

**需求** = 360搜索「相关搜索」词（真实搜索行为，高购买意图词可数）
**供给** = 搜狗微信文章存量 + 标题信号

## 八-C、三类一票否决（每条都有真实反例）

### ① 免费白嫖词 → 用户不是要工具，是要免费

相关搜索出现《永久免费版》《在线免费》《破解》。

**真实反例：`录音转文字`**
供给侧看是完美方向：微信仅 1000 篇（低供给），标题里 **4 条「已有付费工具」
信号**。只看供给会判满分。
但相关搜索是《录音转文字永久免费版》《豆包录音转文字在线免费使用》。
**这是价格战，不是需求。** 评分 10 → 3。

规则：≥4 条免费词封顶 3 分，≥2 条封顶 6 分。

### ② 垄断品牌词 → 该搜索词已被占死

相关搜索出现具体产品名（豆包、讯飞、剪映、鲁青、金蝶…）。
用户在找**那个产品**，不是找解决方案。

**真实反例：`试卷排版`** 9 条高意图词里 3 条是《鲁青答题卡制作工具》。

规则：出现即封顶 4 分。

### ③ 壁垒归零 → 你做完守不住

微信标题出现 `vibecoding`、`我自己做了`、`源码`、`一行代码`。

**真实反例：`房贷提前还款计算器`**
相关搜索里 **6 条高购买意图词，需求看起来很旺**。但标题里躺着
《一天时间 vibecoding 实现房贷提前还款计算器》。
**需求旺 + 壁垒零 = 你进去就是给别人做嫁衣。**

最危险的陷阱：所有需求指标都亮绿灯，只有这一个信号在报警。
规则：出现即封顶 3 分。

### 中文特有的分类陷阱

**B2B 的价格词是正信号，别误伤。**《收费价目表》《报价明细表》《费用》《成本》
在 B2B 语境下是**强购买意图**（用户在评估预算），不是白嫖。

## 九-C、中文引擎的限流防护（重要）

**搜狗微信连续请求会静默返回空页面，而不是报错。** 如果不处理，工具会把
"没抓到数据"误读成"存量 0 篇"，得出**完全相反**的结论。

脚本已内建：
- 空响应退避重试（25s / 50s），**不当作 0**
- 始终取不到时输出 `🟡 黄(不完整)` 并加否决项，**绝不给绿灯**
- 实测限流约 45 秒解除

**看到「黄(不完整)」就隔几分钟重跑，不要将就。**

## 十-C、中文引擎校准锚点

| 方向 | 分 | 裁决 | 卡在哪 |
|---|---|---|---|
| 代账公司对账单 | 8 | 🟢 | — |
| 淘宝标题优化 | 8 | 🟢 | — |
| 发票批量导出excel | 6 | 🟡 | 少量免费词 |
| 试卷排版工具 | 5 | 🟡 | 鲁青已占位 |
| 公众号排版 | 5 | 🟡 | 4100 篇高供给 |
| 录音转文字 | 3 | 🔴 | 免费白嫖 + 豆包 |
| 图片批量加水印 | 3 | 🔴 | 免费白嫖 |
| 房贷提前还款计算器 | 3 | 🔴 | 壁垒归零 |

存量参照：`摸鱼` 8580 / `AI写作` 5887 / `公众号排版` 4100 / `去重工具` 2009 /
`录音转文字` 1000 / `发票批量导出` 614 / `代账对账单` 511。
**1500 以下才值得看，3500 以上基本没戏。**

## 十一-C、中文引擎的付费验证（人工，10 分钟）

扫描能证明「需求旺 + 供给少」，但**证明不了有人真的掏过钱**。

去**闲鱼**搜该关键词，记录：

```
关键词：
有没有人在卖同类产品/服务：有 / 无
价格：
成交/想要数：
评价原文：
```

判读：
- **有人卖且有成交** → 直接开做
- **有人卖但无成交** → 需求可能是伪的，或定价错了
- **没人卖** → 换更窄的关键词重扫

为什么是闲鱼：它是唯一能看到**真实成交**的地方。搜索量是意图，成交是事实。

## 最后：这个 skill 的边界

**它做的是**：把"这个方向竞争激烈吗、有没有人在守"从感觉变成可复现的实测。

**它不做**：证明有人愿意付钱。两个引擎都是**意图/供给数据**，不是成交数据。
最终决定永远来自第八节的付费验证。

**它看不到**：消费级市场、非开发者生态。遇到这类方向要主动说明局限，
不要在数据不足时给出绿灯。
